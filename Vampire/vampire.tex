\abstract{%
	We improve SATCoP performance by resetting the connection tableau often.
	This causes more and more varied SAT statements to be added to the SAT prover, which causes it to saturate faster.
	The resulting prover solves problems faster and in fewer steps than SATCoP and the current state-of-the-art tableau provers.
}

\subsection{Tableau Solving Methods}

Minimalist tableau-style provers based on Prolog have been used with great success since the release of leanTAP in 1995\cite{beckertLeanTAPLeanTableaubased1995}, and have consistently achieved high rankings in solving FOF and CNF problems in the Thousands of Problems for Theorem Provers (TPTP) library\cite{sutcliffe12thIJCARAutomated2025}.

Rather than working like saturation provers such as Vampire\cite{riazanovDesignImplementationVAMPIRE2002}, which repeatedly derive new clauses from the current clause set until they derive a contradiction or reach saturation, tableau-based provers attempt to create a Connection Tableau with ground terms.
The prover builds a tree, where each node corresponds to a particular clause of the problem in conjunctive normal form, using one of the following four steps.

leanCoP improves on earlier connection-tableau provers by combining a very small Prolog implementation with aggressive restricted backtracking\cite{ottenLeanCoPLeanConnectionbased2003,ottenLeanCoP20}.
Successful reduction and extension steps commit with a Prolog \emph{cut} (\texttt{!}), pruning alternative continuations and often reducing search substantially.
To maximise the variety of substitutions in the tableau the maximum height of the tree is constrained, and each subsequent \step{Start} increases this height.
A similar technique is later used in SATResetCoP, which is presented in this paper.

meanCoP revisits this design by separating the effects of reduction cuts and extension cuts, and by replacing leanCoP's particularly strong pruning with more selective exclusive cuts\cite{farberCuriouslyEffectiveBacktracking2024}.
In particular, meanCoP commits only when a successful proof step rules out sibling alternatives at the current choice point, and otherwise allows ordinary backtracking to continue\cite{farberCuriouslyEffectiveBacktracking2024}.
This keeps much of the practical benefit of cut-based control while avoiding some of the unnecessary incompleteness and over-commitment of the original leanCoP strategy\cite{farberCuriouslyEffectiveBacktracking2024}.

The leanCoP line has also been extended in several other directions.
Functional and machine-learning-guided connection provers refine proof-step ordering and clause selection\cite{farberMachineLearningGuidance2021}, rlCoP and plCoP add Monte Carlo Tree Search and reinforcement-learning-based control to leanCoP-style proof search\cite{Kaliszyk2018RLTP,zomboriPrologTechnologyReinforcement2020a}, and recent work on proof syntax and certification makes connection proofs easier to exchange and verify\cite{farberMachineLearningGuidance2018,ottenSyntaxConnectionProofs2023}.
