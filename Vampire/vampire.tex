\begin{abstract}
	We improve \cop{PySATCoP} performance by resetting the connection tableau often.
	This causes more and more varied SAT statements to be added to the SAT prover, which causes it to saturate faster.
	The resulting prover solves problems faster and in fewer steps than \cop{PySATCoP} and the current state-of-the-art tableau provers.
\end{abstract}

\section{Preliminaries}

\subsection{Tableau Solving Methods}

Minimalist tableau-style provers based on Prolog have been used with great success since the release of leanTAP in 1995\cite{beckertLeanTAPLeanTableaubased1995}, and have consistently achieved high rankings in solving FOF and CNF problems in the Thousands of Problems for Theorem Provers (TPTP) library\cite{sutcliffe12thIJCARAutomated2025}.

Rather than working like saturation provers such as Vampire\cite{riazanovDesignImplementationVAMPIRE2002}, which repeatedly derive new clauses from the current clause set until they derive a contradiction or reach saturation, tableau-based provers attempt to create a Connection Tableau with ground terms.
The prover builds a tree, where each node corresponds to a particular clause of the problem in conjunctive normal form, using one of the following four steps.

\begin{figure}[h]
	\todobox{Add a diagram and/or a description.}
	\caption{Description of the operations of Tableau calculus\cite{farberCuriouslyEffectiveBacktracking2024}.}
\end{figure}

\cop{leanCoP} improves on earlier connection-tableau provers by combining a very small Prolog implementation with aggressive restricted backtracking\cite{ottenLeanCoPLeanConnectionbased2003,ottenLeanCoP20}.
Successful \step{Reduction} and \step{Extension} steps commit with a Prolog \step{cut} \texttt{(!)}, pruning alternative continuations and often reducing search substantially.
To maximise the variety of substitutions in the tableau the maximum height of the tree is constrained, and each subsequent \step{Start} increases this height.
A similar technique is later used in \cop{SATResetCoP}, which is presented in this paper.

\cop{meanCoP} revisits this design by separating the effects of \step{Reduction} cuts and \step{Extension} cuts, and by replacing \cop{leanCoP}'s particularly strong pruning with more selective exclusive cuts\cite{farberCuriouslyEffectiveBacktracking2024}.
In particular, \cop{meanCoP} commits only when a successful proof step rules out sibling alternatives at the current choice point, and otherwise allows ordinary backtracking to continue\cite{farberCuriouslyEffectiveBacktracking2024}.
This keeps much of the practical benefit of cut-based control while avoiding some of the unnecessary incompleteness and over-commitment of the original \cop{leanCoP} strategy\cite{farberCuriouslyEffectiveBacktracking2024}.

The \cop{leanCoP} line has also been extended in several other directions.
Functional and machine-learning-guided connection provers refine proof-step ordering and clause selection\cite{farberMachineLearningGuidance2021}, \cop{rlCoP} and \cop{plCoP} add Monte Carlo Tree Search and reinforcement-learning-based control to \cop{leanCoP}-style proof search\cite{Kaliszyk2018RLTP,zomboriPrologTechnologyReinforcement2020a}, and recent work on proof syntax and certification makes connection proofs easier to exchange and verify\cite{ottenSyntaxConnectionProofs2023}.

\subsection{SATCoP and Similar Methods}

Grounded clauses generated in Tableau extensions are added to a SAT solver.
The SAT solver resulting in an unsatisfiable set of ground clauses is sufficient to prove that the entire problem is unsatisfiable.

\section{Research Vehicle}

\subsection{\cop{SATResetCoP} Specification}
\label{satresetcop}

We propose implementing a new tableau prover, based on \cop{SATCoP}, but whose tableau prover attempts to saturate the SAT prover rather than to close the tableau.

Successive experimentation resulted in a simple hypothesis: aggressively resetting the tree when the SAT solver stops growing results in a larger quantity and variety of SAT statements added to the solver, which results in reaching a SAT unsatisfiability proof faster.

\cop{SATResetCoP} uses the same substitution and SAT prover unsatisfiability technique as \cop{PySATCoP}.
However, instead of following \cop{leanCoP}'s tableau guidance strategy, it prioritises resetting the tableau often.
\todo{I think some pseudocode would be better than this list.}
\begin{enumerate}
	\item Choose the next \step{Reduction} or \step{Extension} depending on the status of the selected literal in the SAT model, in Rawson~and~Reger\cite[\SS 9.1]{eliminatingModels}.
		\begin{enumerate}
			\item Steps whose selected literal is \texttt{true} in the SAT model.
			\item Steps whose selected literal is unknown in the SAT model.
			\item Steps whose selected literal is \texttt{false} in the SAT model.
		\end{enumerate}
	\item \step{Cut} \texttt{(!)} reductions and extensions, as in \cop{leanCoP}.
	\item If the next action is a \step{Backtrack}, then \step{Reset} the entire tree from scratch.
	\begin{enumerate}
		\item If new SAT clauses were added in this tree, keep its same maximum height.
		\item Otherwise, attempt to make a deeper tree and increase its maximum height by 1.
	\end{enumerate}
\end{enumerate}

Just like \cop{PySATCoP}, this approach is sound.
While it is less complete than \cop{PySATCoP} and other \cop{leanCoP} variants, the speed at which it proves unsatisfiability of first-order problems can result in a larger amount of problems solved in a bounded amount of time or steps.
It might be useful to incorporate \cop{SATResetCoP} into the initial steps of a more complete schedule.

\subsection{Python Implementation}

As a testbed for out experiments we use the Connections Prober by Rømming et.\ al\cite{connections_2023}, which provides an implementation of leanCoP-style provers.

The connections prover makes it easy to implement different strategies to guide the tableau proof.
This makes implementing the guidance of \cop{SATResetCoP} simple and its code easy to read and evaluate.

The source code for this implementation is present in \url{https://github.com/mfixman/resetsatcop}, and is released under the GNU Lesser General Public Licence\cite{lgpl}.

\subsection{TPTP Benchmarking}

Along with out implementation of \cop{SATResetCoP}, \cop{PyCoP} allows us to reimplement \cop{PyLeanCoP} and \cop{PySATCoP} in its own backend.
This provides a fairer baseline for comparison.

We run \cop{SATResetCoP} along with our versions of these two connection tableau strategies, along with a strategy that chooses the first possible action as control, on the \num{8344} CNF problems and \num{9091} FOF problems of all 50 categories \todo{Categories?} containing at least one of these problems from the Thousands of Problems for Theorem Provers (TPTP) library\cite{tptp}.

The library provides a varied set of problems that's a standard way to prove first-order provers.
It also provides declared statuses for these problems, which are a useful sanity check for false unsatisfiability results.

\section{Experimental Evaluation}

\subsection{Experiment Design}

The connections prover provides with \cop{PyCoP}, a simple prover that chooses the first legal non-backtrack action at each point and resets the tree with an increased maximum height saturated.

As a second control policy we use our implementation of \cop{leanCoP}\cite{ottenLeanCoP20}, \cop{PyLeanCoP}.
This is a Python version of the \cop{leanCoP} Prolog implementation, with the two recommended predicates used in the first step of the schedule by Otten\cite[\SS 5.5]{ottenLeanCoP20}.
\begin{description}
	\item[\texttt{cut}] Choose one choice from each extension and reduction and backtrack afterwards, in a similar way to to Prolog's \texttt{!} operator.
	\item[\texttt{comp(7)}] The prover does iterative deepening of height 1 at a time when the tree is saturated until reaching maximum height 7.
		Afterwards limits on height are restricted.
\end{description}

These kinds of simple policies tend to be very effective in tableau provers\cite{Otten2023leanCoP20}.

\subsubsection{Soundness Verification: Problem Satisfiability}

The problems in the TPTP library have a helpful specification of the satisfiability of different types of problems\cite{tptp}.
This is useful as a sanity-check: a sound solver should never ``prove'' unsatisfiability on a satisfiable problem, and their authors should be wary when proving unsatisfiability on an open or unknown problem.
Note that this is not a way to prove soundness of the solver, but to check that it does not exhibit false unsatisfiability results on problems declared satisfiable or countersatisfiable.

We make a second run of \cop{SATResetCoP} with a longer 10-minute limit, whose results can be seen in \cref{sat_proof}.
These results do not show any negative results.
