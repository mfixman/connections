\begin{abstract}
	We improve SATCoP performance by resetting the connection tableau often.
	This causes more and more varied SAT statements to be added to the SAT prover, which causes it to saturate faster.
	The resulting prover solves problems faster and in fewer steps than SATCoP and the current state-of-the-art tableau provers.
\end{abstract}

\section{Preliminaries}

\subsection{Tableau Solving Methods}

Minimalist tableau-style provers based on Prolog have been used with great success since the release of leanTAP in 1995\cite{beckertLeanTAPLeanTableaubased1995}, and have consistently achieved high rankings in solving FOF and CNF problems in the Thousands of Problems for Theorem Provers (TPTP) library\cite{sutcliffe12thIJCARAutomated2025}.

Rather than working like saturation provers such as Vampire\cite{riazanovDesignImplementationVAMPIRE2002}, which repeatedly derive new clauses from the current clause set until they derive a contradiction or reach saturation, tableau-based provers attempt to create a Connection Tableau with ground terms.
The prover builds a tree, where each node corresponds to a particular clause of the problem in conjunctive normal form, using one of the following four steps.

\begin{figure}[h]
	\fbox{\parbox[c][75pt]{\textwidth}{\centering \todo{Add a diagram and/or a description.}}}
	\caption{Description of the operations of Tableau calculus\cite{farberCuriouslyEffectiveBacktracking2024}.}
\end{figure}

leanCoP improves on earlier connection-tableau provers by combining a very small Prolog implementation with aggressive restricted backtracking\cite{ottenLeanCoPLeanConnectionbased2003,ottenLeanCoP20}.
Successful \step{Reduction} and \step{Extension} steps commit with a Prolog \step{cut} \texttt{(!)}, pruning alternative continuations and often reducing search substantially.
To maximise the variety of substitutions in the tableau the maximum height of the tree is constrained, and each subsequent \step{Start} increases this height.
A similar technique is later used in SATResetCoP, which is presented in this paper.

meanCoP revisits this design by separating the effects of \step{Reduction} cuts and \step{Extension} cuts, and by replacing leanCoP's particularly strong pruning with more selective exclusive cuts\cite{farberCuriouslyEffectiveBacktracking2024}.
In particular, meanCoP commits only when a successful proof step rules out sibling alternatives at the current choice point, and otherwise allows ordinary backtracking to continue\cite{farberCuriouslyEffectiveBacktracking2024}.
This keeps much of the practical benefit of cut-based control while avoiding some of the unnecessary incompleteness and over-commitment of the original leanCoP strategy\cite{farberCuriouslyEffectiveBacktracking2024}.

The leanCoP line has also been extended in several other directions.
Functional and machine-learning-guided connection provers refine proof-step ordering and clause selection\cite{farberMachineLearningGuidance2021}, rlCoP and plCoP add Monte Carlo Tree Search and reinforcement-learning-based control to leanCoP-style proof search\cite{Kaliszyk2018RLTP,zomboriPrologTechnologyReinforcement2020a}, and recent work on proof syntax and certification makes connection proofs easier to exchange and verify\cite{ottenSyntaxConnectionProofs2023}.

\subsection{SATCoP and Similar Methods}

Rawson and Reger integrate a SAT prover into a clausal tableau system based on leanCoP\cite{eliminatingModels}.
Grounded clauses generated in Tableau extensions are added to a SAT solver.
The SAT solver resulting in an unsatisfiable set of ground clauses is sufficient to prove that the entire problem is unsatisfiable.

This technique of combining a saturation-style prover with tableau guidance is surprisingly effective at finding solutions before the tableau is closed.
As noted by Rawson and Reger, there is a wide range of undiscovered improvements to this technique.

\subsection{ResetSATCoP Specification}

We propose implementing a new tableau prover, based on SATCoP, but whose tableau prover attempts to saturate the SAT prover rather than to close the tableau.

Successive experimentation resulted in a simple hypothesis: aggressively resetting the tree when the SAT solver stops growing results in a larger quantity and variety of SAT statements added to the solver, which results in reaching a SAT unsatisfiability proof faster.

ResetSATCoP\footnotemark{} uses the same substitution and SAT prover unsatisfiability technique as SATCoP.

However, instead of following leanCoP's tableau guidance strategy, it prioritises resetting the tableau often.

\subsection{Python Implementation}

As a testbed for out experiments we use a Python implementation of leanCoP, PyCoP.

This program implements classical tableau calculus and supports leanCoP-style \textsc{cut}s, different maximum heights, and adding a SAT solver to implement a SATCoP-style prover.

Most importantly, the program allows us to implement different strategies to guide the tableau proof.
This makes implementing the guidance of ResetSATCoP simple and its code easy to read and evaluate.

The source code for this implementation is present in \url{https://github.com/mfixman/resetsatcop}, and is released under the GNU Lesser General Public Licence\cite{lgpl}.
