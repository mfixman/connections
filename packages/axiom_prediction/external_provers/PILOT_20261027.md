# Vampire ordinary-first support pilot

On 27 October 2026 the user requested a local test of the shared 40s ordinary
search / 20s learned top-1 support policy, then directed the work to focus on
Vampire. The comparison did not improve on ordinary Vampire: all five arms
proved exactly the same 42 of 54 problems, with no guided-stage proofs.

| Configuration | Proofs /54 | PAR2 s |
| --- | ---: | ---: |
| Ordinary LRS Vampire | 42 | 28.145 |
| Ordinary 40s then learned support-1 (`sos all`) | 42 | 27.918 |
| Same with shuffled ranking | 42 | 27.840 |
| Ordinary 40s then learned support-1 (`sos on`) | 42 | 27.930 |
| Same `sos on` variant with shuffled ranking | 42 | 27.990 |

There were zero paired gains or losses. Every proof came from the ordinary
process. The small PAR2 differences therefore come entirely from timing of
ordinary-stage shared successes, before scoring; they do not demonstrate a
learned speedup. The slowest ordinary baseline success took 28.17s.

The sample contains one known-provable CNF variant per family, selected from
217 eligible remaining families in checkpoint split scheme 4, part 9. Sampling
seed: 2026102712. Families recovered from saved Vampire experiment manifests
and problem-list JSON were excluded. This is a new local Vampire sample, not a
claim that the inputs were unseen in earlier Prover9 or Connections experiments.

Each arm received a 60s end-to-end wall deadline on the same pinned CPU per
problem, with rotated arm order. Alternative stages used their actual remaining
internal allowance. A running ordinary process was paused at 40s and resumed
after early guidance failure. Scoring used the frozen Torok checkpoint inside
the 20s allowance; the existing 256-preprocessed-clause guard remained enabled.
Native seed and shuffled-ranking seed were both 1, algorithm LRS, memory limit
2,048 MB. There was no SInE stage and AVATAR retained its ordinary setting.

The complete 270-run batch took 603.16s with 18 single-core proof workers on
CPUs 0–17. The process registry was empty after cleanup, source hashes did not
change during the run, and all 270 outcomes agreed with retained complete-proof
markers. No Prover9 or HPC searches were run in this pilot.

Each guided variant made 12 attempts. Six exceeded the clause guard and
returned to ordinary search. Buffered output hid the rankings of the other
six killed attempts. A separate 20s, six-worker line-buffered diagnostic on
those inputs confirmed that all six computed support selections, with reported
graph-and-inference times of 0.156–0.183s, but none proved the problem. Those
diagnostics are excluded from the primary comparison. SYN914-1 had only one
axiom, so its selected support was not a nontrivial ranking choice.

The result rejects this particular late top-1 schedule as a measured coverage
improvement on the pilot; it does not establish that all learned guidance is
ineffective. The next investigation should examine other interventions and
properties on development data before testing a frozen candidate elsewhere.
